# Add a Roast Room advisor in Codex

Resolve the repository root three levels above this skill folder. Run the shared scripts from that root and use its paths even if the terminal starts elsewhere. Read `.claude/skills/newroaster/SKILL.md` for the shared workflow and load the linked references as each phase needs them. Apply the following Codex instructions where the workflows differ.

- Accept `$newroaster <full name> [--quick | --deep] [--pillar "<pillar>"] [--default]` or the equivalent in plain language. Standard depth and on-call membership are defaults. Batch material questions with Codex's available input tool or chat. A full default board needs an explicitly named replacement before using `--swap`.
- For `$newroaster portrait <name>`, look up the existing seat and run only the portrait phase. If an advisor already exists and the user only wants them on the default board, use `$roast-room board`. Check the roster and filesystem for key, slug, and short-name collisions before building a new seat.
- Use Codex web search and the shared fetch script for lawful source collection. Use supplied material only for the user or a consenting advisor. Keep raw sources and intermediate work under ignored `build/<slug>/`. Record what the fetches actually yielded. If the requested depth is infeasible, report the shortfall and get direction before publishing a thinner advisor.
- Use isolated Codex subagents for source extraction and the three writing assignments when delegation is available and permitted. Give each extractor only its assigned sources and the shared extraction prompt. Give each writer the verified notes, brain spec, and its assigned files. Run in waves within the active agent limit. If delegation is unavailable, do each batch and writing assignment sequentially and report that choice.
- Stage the eight brain files and persona under `build/<slug>/`. Run the shared quote checker on notes, the complete brain, and a sample consult before publishing. Verify short quotes against the cited text and check that paraphrases and framework IDs match their sources. For the sample consult, give a fresh read-only Codex agent the staged persona and brain paths plus the shared single-seat prompt, or run it sequentially. Treat the persona's Claude frontmatter as metadata. Confirm the answer applies the pillar and cites real sources. Fix material failures and retest before registration.
- Publish the verified brain and persona in the shared `.claude/` paths and register them using `add_seat.mjs`. Keep the advisor on call unless the user asked for default membership. Check the resulting entry and board, then add the natural tensions in the shared seats reference. Both runtimes and the viewer use the same roster. Codex reads the persona at run time.
- For portraits, use the shared photo-based pipeline and check all four finished frames. Use the configured Kie.ai integration for public photos. Confirm permission before uploading a private photo to that service. When the portrait integration or dependencies are unavailable, finish the advisor with the viewer's placeholder and give the `$newroaster portrait <name>` follow-up. For a portrait-only request, report missing prerequisites directly.
- Report the advisor's pillar, source count and coverage, board membership, verification, and portrait status. Give `$roast-room ask <key>` and `$roast-room --seats <key>,buffett` as ways to use the new advisor.
